# Node publication

The public repository contains the Fib 1 foundation and publication code only. Exported vault data, copied vault media, activation bundles, and credentials do not belong in it.

## Five-layer contract

- **Anchor:** The versioned Fib 1 foundation is small and stable. Its Pages workflow runs only by manual dispatch; it is never regenerated by a content update.
- **Drift:** Each Obsidian-derived branch is rebuilt, validated, and published independently by selecting one branch in the node workflow.
- **Vault:** Private bundles and media live in R2, outside Git history.
- **Activation:** The Worker resolves tokens, progression, chamber rules, JSON, and private media.
- **Recovery:** Source, generated artifacts, and publication credentials remain separate so a branch can be replaced without rebuilding the world.

## Private source repository

Create a private repository with this generated layout:

```text
vault-archive.json
vault-index.json
website/assets/vault/...
```

Export the local Obsidian vault into a checkout of that repository:

```powershell
.\import-threshold-vault.ps1 `
  -OutputDir C:\path\to\threshold-node-source `
  -AssetOutputDir C:\path\to\threshold-node-source\website\assets\vault
```

Review and push only that private source repository. Do not add its output to the foundation repository.

## GitHub configuration

Set these Actions variables:

- `NODE_SOURCE_REPOSITORY`: `owner/private-source-repository`
- `R2_NODE_BUCKET`: the R2 bucket bound as `NODE_BUNDLES`

Set these Actions secrets:

- `NODE_SOURCE_TOKEN`: fine-grained token with read access to the private source repository
- `THRESHOLD_NODE_SECRET`: shared HMAC secret used by the publisher
- `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`: R2 object read/write credentials
- `CLOUDFLARE_ACCOUNT_ID`: Cloudflare account containing the bucket

Run **Publish Activated Node Bundles** after updating the private source repository and select the changed branch. The workflow tests the publisher, creates only that branch's topology-referenced bundles and media, and synchronizes only `nodes/<branch>/` and `assets/<branch>/` to R2. It writes the audit record to `manifests/<branch>.json`.

Use `python tools/publish_node_bundles.py --branch all` only for local recovery validation. Routine publication must name one branch.

Bind the bucket to the Worker as `NODE_BUNDLES`. Configure a separate random `SEED_SECRET` for its progression cookie; the activation token secret remains publication-only.
