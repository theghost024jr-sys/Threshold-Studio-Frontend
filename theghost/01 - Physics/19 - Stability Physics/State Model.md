Definition
The State Model defines how nodes (artifacts, roles, forces, entities) hold, express, and change state within the Field.
It describes:
• 	what a state is
• 	how a state is represented
• 	how a state transitions
• 	how the system interprets those transitions
A state is not a label.
A state is a configuration of force.

Purpose
To ensure that:
• 	every node has a coherent internal condition
• 	state changes are interpretable
• 	transitions follow the System of Force
• 	the Field can track and update the Matrix
• 	the Consequence Engine has stable inputs
• 	resolution and activation have something to act upon
The State Model is the substrate of the entire engine.

Core Components of State
Every node has the following structural components:
1. Baseline State
The node’s neutral, unactivated condition.
This is the state the Field returns to after resolution.
2. Active State
The node’s condition when one or more vectors are engaged.
Examples:
• 	a role being held
• 	a gift in progress
• 	a threshold being approached
• 	drift accumulating
Active states are temporary and dynamic.
3. Tension State
The node’s condition when imbalance, drift, or unresolved force is present.
Tension states require resolution.
4. Transitional State
The node’s condition during a crossing, transformation, or collapse.
Transitional states are unstable by design.
5. Resolved State
The node’s condition after resolution mechanics complete.
Resolved states may differ from baseline states due to transformation.

State Variables
Each node tracks the following variables:
1. Force Level
How much active force is currently acting on the node.
2. Vector Engagement
Which vectors are currently influencing the node.
3. Drift Level
How much unresolved tension the node is carrying.
4. Role Status
Whether the node is holding, releasing, or collapsing a role.
5. Zone Context
Which environmental forces are shaping the node.
6. Lineage Position
Where the node sits in its lineage chain.
7. Threshold Proximity
How close the node is to crossing a boundary.
These variables define the node’s full state.

State Transitions
A state transition occurs when:
• 	a vector activates
• 	a force is applied
• 	a gift is exchanged
• 	a threshold is crossed
• 	drift accumulates
• 	drift resolves
• 	a role is invoked or collapsed
• 	a zone exerts influence
Transitions are governed by:
• 	Activation Logic
• 	Invariants
• 	Consequence Engine
• 	Resolution Mechanics

Transition Types
1. Activation Transition
Baseline → Active
Triggered by vector activation.
2. Drift Transition
Active → Tension
Triggered by imbalance or neglect.
3. Crossing Transition
Active/Tension → Transitional
Triggered by threshold movement.
4. Collapse Transition
Tension → Transitional
Triggered by unresolved force exceeding stability.
5. Resolution Transition
Transitional/Tension → Resolved
Triggered by Resolution Mechanics.
6. Return Transition
Resolved → Baseline
Triggered by stabilization of force.

State Integrity Rules
1. Identity is preserved
State changes cannot erase the node’s essence.
2. Motion is conserved
State changes must account for all force.
3. No spontaneous transitions
All transitions require activation conditions.
4. No unresolved states
All tension must resolve.
5. No contradictory states
A node cannot hold mutually exclusive states simultaneously.

Function
The State Model:
• 	provides stable inputs to the Consequence Engine
• 	ensures coherent transitions
• 	maintains identity through change
• 	tracks drift, tension, and activation
• 	enables resolution
• 	keeps the Matrix consistent
• 	allows the Field to remain interpretable
Without a State Model, the system would have motion but no memory.
With it, the system becomes a living engine.

• 	Consequence Engine → interpreter of state transitions
• 	Activation Logic → triggers of state change
• 	Resolution Mechanics → completion of state change
