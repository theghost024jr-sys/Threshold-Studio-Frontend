Overview Node Activation Protocols define how and when a node becomes active within Threshold’s world‑graph. A node is considered active when it: • appears in the current canvas • participates in structural relationships • influences or is influenced by system physics • becomes available for player interaction Activation is not cosmetic — it is a structural event governed by strict architectural rules.

Activation States Nodes move through three canonical states:

  1. Dormant — exists in the system but not visible

  2. Active — visible and structurally connected

  3. Engaged — participating in dynamic interactions (fields, collapse, emotion, etc.) The protocols below define how transitions occur.

  4. Activation by Revelation (Player reveals an existing node) Trigger Condition The player selects an option corresponding to a node that already exists somewhere in the system. System Behavior • Locate the dormant node • Pull it into the current canvas • Establish a directed edge from the active node → revealed node • Update node state to Active Meaning The node was always part of the world; the player has simply made it visible. Example Revealing Dust Hare.md when entering a Drift‑heavy zone.

  5. Activation by Generation (Player creates a new node) Trigger Condition The player selects an option that does not correspond to any existing node. System Behavior • Generate a new node • Assign canonical name and folder placement • Link active node → new node • Initialize node state as Active • Register node in system indices (species, artifacts, emotional physics, etc.) Meaning The world expands because the player touched an unmapped conceptual edge. Example Creating Glass‑Winged Lurker.md as a new species.

  6. Activation by Connection (Player connects two existing nodes) Trigger Condition The player selects an option that references a node already present in the current canvas. System Behavior • No new node is created • Draw a new edge between the two existing nodes • Update both nodes to Engaged if the connection implies interaction • Reveal hidden structural truth Meaning The player uncovers a relationship that already existed in the architecture. Example Connecting Mist → Stone to reveal layer‑layer interaction.

Activation Rules Rule 1 — No Upward Links Nodes may not activate by linking upward into meta‑systems or higher layers. Rule 2 — No Lateral Layer Links Layer nodes may not connect sideways unless explicitly defined by Field Architecture. Rule 3 — Activation Requires Contact A node cannot activate without: • player choice • system prompt • or structural dependency No spontaneous activation. Rule 4 — Activation Is Permanent Once a node becomes active, it remains part of the world‑graph unless explicitly collapsed. Rule 5 — Activation Must Respect Folder Logic New nodes must be placed in the correct canonical folder.

Engagement Protocols A node becomes Engaged when: • it participates in emotional physics • it interacts with a field (Drift, Mist, Shimmer, etc.) • it enters collapse adjacency • it forms a recursive or symbolic relationship • it becomes part of a dynamic system (Witness Spiral, Shimmer Field, etc.) Engaged nodes influence: • collapse propagation • emotional resonance • field behavior • symbolic density

Deactivation Protocols Nodes may return to Dormant only when: • the player leaves the zone • the system collapses the moment • the node is explicitly suppressed by collapse physics • the narrative arc ends Deactivation never deletes the node — it simply removes it from the active canvas.
