Overview Canvas Generation Logic defines how a canvas populates, expands, and reveals structure in response to player actions. A canvas is not a static diagram — it is a dynamic node‑graph that grows according to: • Player Choice Trees • Node Activation Protocols • System Architecture rules • Link Logic • Folder Logic A canvas is the local expression of the world‑graph at a given moment.

Core Principles Canvas generation follows five architectural principles:

  1. Locality — only nodes relevant to the current moment appear
  2. Directionality — links follow system architecture (no upward or lateral violations)
  3. Minimality — only necessary nodes are shown; no clutter
  4. Reactivity — canvases update immediately when choices are made
  5. Continuity — once a node appears, it remains unless collapsed or exited These principles keep canvases readable, stable, and structurally honest.

Canvas Generation Flow Every canvas follows the same generation sequence:

Prompt → Choice Tree → Node Activation → Canvas Update → Structural Check

Let’s break that down.

  1. Prompt Node Appears A canvas always begins with a Prompt Node, representing the moment the system asks: • “What do you create” • “What do you perceive” • “What emerges” • “What collapses” • “What responds” This node anchors the entire generation sequence.

  2. Player Choice Tree Activates The player’s selection determines which of the three creation paths fires: • Reveal Existing Node • Create New Node • Connect Existing Nodes This choice determines the type of canvas update.

  3. Node Activation Protocol Fires Depending on the choice: Reveal Existing Node • Pull node into canvas • Link: Create New Node • Generate new node • Place in canonical folder • Link: Connect Existing Nodes • Draw new edge between nodes • Update both to Engaged state This is the structural heart of canvas generation.

  4. Canvas Updates After activation, the canvas performs: A. Node Placement Nodes are placed according to: • Layer hierarchy • Field interactions • Symbolic resonance • Collapse adjacency • Spatial logic of the diagram B. Edge Rendering Edges are drawn: • Downward (allowed) • Never upward • Never sideways between layers • Freely between non‑layer nodes C. Visibility Rules Only nodes relevant to the current moment appear.

  5. Structural Check After updating, the canvas runs a structural integrity check: Checks for: • Forbidden upward links • Forbidden lateral layer links • Missing canonical nodes • Broken references • Orphaned nodes • Violations of folder logic If a violation is detected, the canvas: • refuses the link • or repositions the node • or suppresses the node entirely This is why canvases “push back” when something is architecturally wrong.

Canvas Types There are three canonical canvas types:

  1. Layer Canvases Represent the internal structure of a layer. Follow strict downward‑only rules.
  2. System Canvases Represent architecture, naming, link logic, etc. Follow meta‑system rules.
  3. Moment Canvases Represent a single moment of play. Follow dynamic, reactive rules. Each type uses the same generation logic but with different constraints.

Canvas Persistence Rules A canvas persists: • until the moment ends • until the player leaves the zone • until collapse suppresses it • until the system transitions to a new canvas Nodes remain active unless explicitly collapsed.
