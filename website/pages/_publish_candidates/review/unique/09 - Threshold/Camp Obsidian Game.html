🎮 THE OBSIDIAN GRAPH META‑GAME

A super‑proto‑prototype where players manipulate the knowledge world under constraints

At its core, you’re doing this:

  • The graph = the world
  • The markdown files = entities, locations, items, characters, biomes
  • The links = actions, relationships, mechanics
  • The players = agents with asymmetric abilities
  • The rules = physics of the world
  • The ground rules = constraints that create interesting behavior

This is exactly how early system designers prototype games before touching code.

🧱 1. The Ground Rules (the physics layer)

These are the constraints that make the game playable and prevent chaos.

Examples you already hinted at:

Rule 1 — No Editing, Only Expanding

Players cannot change existing notes.
They can only:

  • add new notes
  • add new links
  • add new layers
  • add new biomes
  • add new characters

This forces forward motion and prevents retconning.

Rule 2 — Every Action Must Touch the Graph

No “off‑graph” ideas.
If it’s not linked, it doesn’t exist.

Rule 3 — Every Player Turn Must Produce a New Node or New Link

No null turns.
The world grows every cycle.

Rule 4 — You Can Only Act Through Your Card Ability

This is the asymmetric power structure.

🃏 2. The Ability Cards (the asymmetric agency layer)

This is where the game becomes fun.
Each player draws a card that gives them a unique power over the graph.

Here are the ones you already sketched — plus a few more that fit the system:

Card: The Linker

You may link any character to any layer you find in the graph.

Card: The Scribe

You may fill in any blank .md file with 1–3 sentences of content.

Card: The Biome‑Maker

You may create or link to a biome.
Biomes can contain:

  • environmental rules
  • creatures
  • hazards
  • resources

Card: The Archivist

You may create a new layer and link 3 existing nodes into it.

Card: The Drifter

You may create a node with no links — a mystery node.
Other players must discover its purpose.

Card: The Weaver

You may add a link between any two nodes that were previously unconnected.

Card: The Gatekeeper

You may create a portal (a link that changes the meaning of both nodes).

Card: The Echo

You may duplicate any node and mutate the copy.

Card: The Cartographer

You may create a region (a cluster) and assign 5 nodes to it.

These cards create emergent structure without requiring a plan.

🌀 3. The Turn Cycle (the Gearweave applied to a group)

Each player’s turn is a micro‑Gearweave:

  1. Observe the graph
  2. Interpret their ability
  3. Act by adding a node or link
  4. Explain the change in one sentence
  5. Pass to the next player

This keeps the world alive and prevents stagnation.

🌍 4. Why this becomes a “super proto prototype game”

Because you’re not building a game —
you’re playing the architecture of the game.

The graph becomes:

  • the world map
  • the lore bible
  • the mechanic tree
  • the character roster
  • the region topology
  • the emergent narrative

And because players only expand (not edit), the world grows like a coral reef — organically, unpredictably, but with structure.

This is exactly how early Dwarf Fortress, early MUDs, and early roguelikes were prototyped.
